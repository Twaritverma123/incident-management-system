Java + Spring Boot • MongoDB • Spring Security • REST APIs

Incident Management System

Role-based backend for creating, assigning, tracking and closing incidents.

View GitHub Repository ↗ View Architecture

Backend Architecture

Client / Postman / Angular→ Spring Security→ Controller→ Service→ Repository→ MongoDB

Authentication and authorization are handled by Spring Security. Controllers expose REST APIs, services contain business rules, repositories communicate with MongoDB, and supporting services provide audit logging and email notifications.

Layer Responsibilities

Spring Security

Authentication, BCrypt password verification and role-based authorization.

Controller

Receives REST requests, passes data to services and returns HTTP responses.

Service

Business logic, validations, incident workflow, audit creation and email notification.

Repository

Communicates with MongoDB for persistence and retrieval.

Entity

Represents User, Incident, AuditLog and IncidentStatus data.

MongoDB

Stores users, incidents and audit logs.

Roles

DEVELOPER

Works on assigned incidents and can update their status.

LEAD

Manages incidents, assigns incidents to developers and updates status.

SCRUM_MASTER

Manages incidents, assigns incidents to developers and updates status.

Incident Lifecycle

OPEN→ASSIGNED→IN_PROGRESS→RESOLVED→CLOSED

IncidentService validates status transitions and prevents invalid transitions such as OPEN directly to CLOSED.

REST API Design

MethodEndpointPurpose
POST/user/registerRegister a user
POST/incidentsCreate an incident
GET/incidentsGet all incidents
GET/incidents/{id}Get a single incident
PUT/incidents/{id}/assign?developer=...Assign an incident
PUT/incidents/{id}/status?status=...Update incident status
GET/incidents/{id}/historyGet incident audit history

Data Model

User

id, userName, password, email, roles

Incident

id, incidentNumber, title, description, priority, status, reportedBy, assignedTo, createdAt, updatedAt

AuditLog

id, incidentId, incidentNumber, action, performedBy, description, timestamp

MongoDB database: incident_management • Collections: users, incidents, audit_logs

Security Architecture

HTTP Request→ Spring Security Filter→ Authentication→ Authorization→ Controller

Authentication answers “Who are you?” Authorization answers “What are you allowed to do?”
